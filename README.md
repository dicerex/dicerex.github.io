# Александр Алексеев — портфолио

Одностраничное портфолио на Astro 7 и TypeScript. Русский и английский языки, адаптивная вёрстка, только тёмная тема, светлая типографика и красный акцент. Крупный портрет на первом экране. Проекты расположены по одному на строку: описания и снимки видны сразу, скрывать можно только техническую часть. Шрифты Manrope и JetBrains Mono включены в сборку и не требуют Google Fonts.

## Локальный запуск

Node.js 24 (версия указана в `.nvmrc`):

```sh
nvm use
npm ci
npm run dev
```

Открыть адрес, напечатанный Astro, обычно `http://127.0.0.1:4321`.

```sh
npm run build
npm run preview
```

Сборка запускает проверку типов, создаёт `dist/` и проверяет внутренние ссылки, ресурсы и пути публикации.

## GitHub Pages

Этот каталог `www` — корень Git-репозитория. Файлы из родительского каталога не нужны для установки, сборки и публикации.

1. Создать пустой репозиторий на GitHub без README и дополнительных файлов.
2. Из этого каталога подключить его и отправить ветку:

   ```sh
   git remote add origin https://github.com/USERNAME/REPOSITORY.git
   git push -u origin main
   ```

3. В GitHub: **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Дождаться workflow **Deploy portfolio to GitHub Pages**. Если первый запуск произошёл до настройки Pages, повторить его во вкладке Actions.

Workflow собирает `dist` и публикует только готовый сайт. Репозиторий не должен содержать внешнюю папку `www`: содержимое текущего каталога отправляется непосредственно в корень репозитория.

Адрес и базовый путь определяются через `GITHUB_REPOSITORY`. Поддерживаются и проектный адрес `USERNAME.github.io/REPOSITORY/`, и репозиторий `USERNAME.github.io` в корне домена. Для собственного домена можно задать Actions Variables `SITE_URL` и `BASE_PATH` (значение `/` для корня), а также добавить `public/CNAME`.

Локальная проверка проектного адреса:

```sh
GITHUB_REPOSITORY=example/portfolio npm run build
BASE_PATH=/portfolio/ npm run preview
```

## Содержимое и дизайн

- `src/data/projects.ts` — коммерческие кейсы, подтверждённый владельцем личный вклад, английские описания, галереи и отдельно личные проекты.
- `src/data/i18n.ts` — русские и английские тексты интерфейса и описание разработчика.
- `src/components/T.astro` — переключаемые тексты из доверенных, редактируемых в репозитории данных. Не передавать в этот компонент внешнее содержимое: он поддерживает HTML-разметку.
- `src/components/ProjectArt.astro` — композиции из реальных экранов. Для сайтов компьютерный и мобильный виды накладываются друг на друга, кнопки меняют передний план. Для приложений используется миниатюра телефона. Любой экран можно увеличить.
- `src/components/ProjectCard.astro` — строка проекта с открытым описанием, задачей и снимками; только техническая часть находится в `details`.
- `src/components/Lightbox.astro` — увеличение снимков, переключение стрелками, Escape и возврат фокуса.
- `src/styles/global.css` — адаптивная вёрстка и постоянная тёмная палитра.
- `public/images/projects/<slug>/` — подготовленные публичные снимки.

Сайт содержит девять коммерческих кейсов: Amelia, Вратарницу, Сэйв, GodenDo, Alean, UnitedMission, «Лёд и пламя», HOROSHO и Bestphone. VPN-платформа, Crypto bot и Trade v2 обозначены как личные проекты. Не добавляйте результаты, метрики, сведения о личной роли и скриншоты без проверки с владельцем.

Для всех девяти кейсов подключены реальные снимки, всего пятнадцать. Для шести проектов с веб-интерфейсом есть компьютерный и мобильный виды. HOROSHO и Bestphone сняты с действующих сайтов; в карточках есть ссылки на них. Материалы заказчиков перед добавлением нужно обезличить. Исходное резюме и приватная инвентаризация не входят в репозиторий. Для Сэйв выбран экран входа: предоставленный снимок списка объектов с рабочими номерами и состояниями не скопирован в публичные файлы.

В `engagement` каждого коммерческого проекта хранится подтверждённая владельцем пометка: разработка для ИП Манилов Тимур Викторович, разработка для ООО «Pushmobile» либо частный фриланс. Пометки видны сразу и переведены на английский.

## Языки

RU/EN переключаются на той же странице без перезагрузки. Приоритет выбора: `?lang=ru` или `?lang=en` → сохранённый выбор → язык браузера (русский либо английский). Меняются тексты, подписи снимков, доступные имена кнопок, язык документа и метаданные. Без JavaScript доступны русская версия, все описания и композиции снимков, стандартное раскрытие технических подробностей. Палитра всегда тёмная и не зависит от сохранённых ранее настроек темы.

## Добавление снимков

Положить готовый WebP/PNG в `public/images/projects/<slug>/` и дополнить `screenshots` нужного проекта:

```ts
screenshots: [{
  src: 'projects/amelia/02-product.webp',
  width: 562,
  height: 1280,
  alt: { ru: 'Карточка букета', en: 'Bouquet details' },
  caption: { ru: 'Выбор букета', en: 'Choosing a bouquet' },
}]
```

Первый горизонтальный и первый портретный снимки используются в открытой композиции. Для портретного снимка автоматически используется оформление телефона, для горизонтального — браузера. Когда есть оба формата, они показаны вместе, а кнопки «Компьютер / Телефон» меняют передний план. Диалог поддерживает любое количество снимков; данные и подписи нужно добавлять для обоих языков. После добавления выполнить `npm run build`, чтобы проверить пути.

Предоставленные владельцем снимки используются для Amelia, Вратарницы, Сэйв и GodenDo. Alean и UnitedMission сняты с локальных копий интерфейсов без рабочих серверных обработчиков; исходные проекты не изменялись. Снимок «Лёд и пламя» получен из существующей статической сборки. Сборки для съёмки, промежуточные PNG и инструменты проверки находятся в игнорируемом `.local/`, в публикацию не входят.

## Статус

Это локальная версия портфолио. Описания назначения проектов основаны на коде и предоставленных снимках; блоки «Мой вклад» составлены по рассказу владельца. Они видны сразу на обоих языках. Публикация требует созданного владельцем GitHub-репозитория. Метрики, отзывы и неподтверждённые результаты не добавлены.
